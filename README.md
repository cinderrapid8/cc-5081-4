# 近战格挡 / 招架裁决模块

输入**已确认接触**的攻击事件，输出 `parry`（招架）、`block`（格挡）或 `hit`（受击）。
模块不实现碰撞引擎，只消费碰撞层上报的接触事件；所有时间由外部显式传入，
裁决结果与渲染频率、帧率无关。

## 目录结构

```
src/adjudicator.js   裁决核心（无 DOM、无内部时钟，UMD：Node/浏览器通用）
src/simulation.js    固定步长模拟层 + 最小化接触检测（仅用于产生已确认接触事件）
src/scenarios.js     脚本化场景 A-D，每个场景附独立 expected 预期清单
demo/index.html      Canvas 演示页面（可操作角色、渲染频率切换）
demo/renderer.js     渲染器与输入
demo/main.js         固定步长逻辑 + 渲染节流主循环
samples/contact-events.js  可直接调用裁决接口的事件样例
test/                node:test 测试（单元 / 场景集成 / 帧率不变性 / 无头冒烟）
```

## 运行

```bash
npm test          # 32 个测试
npm run samples   # 打印 5 组接口输入/输出样例
# 浏览器打开 demo/index.html（需经 http 服务，例如 python3 -m http.server）
```

## 裁决规则

资格由四个输入共同决定：角色朝向、防御开始时间、攻击到达时刻、招式性质。

- **普通格挡覆盖区**：以朝向为中心的大扇形（装备决定半角），只要处于防御姿态内持续有效，无短窗口。
- **精准招架窗口**：进入防御姿态后的半开区间
  `[guardStartMs, guardStartMs + parryWindowMs)`，且攻击必须落在更窄的招架扇形内。
  恰好等于窗口结束时刻的事件**不算招架**，退化为格挡（若格挡覆盖区满足）。
- 招式性质：`heavy`（重击）不可招架，窗口内也只能格挡；`slash`/`thrust` 均可招架。
- 同一攻击实例（`instanceId`）跨多个接触点只结算一次，裁决时刻锁定为**首次满足资格的时刻**。
- 装备切换立即改变格挡覆盖规则；退出防御姿态时，所有待裁决接触当场受击。
  已下达的裁决不被后续换装/退出姿态改写。
- 播放防御动作动画本身不进入姿态，不会产生招架（演示按 `G` 可验证）。

## 攻击源编号

`AttackSource` 每次 `cast()` 产生 `src-<源序列号>#<施法序号>` 形式的唯一 `instanceId`，
不同源、同一源重复生成均不会混淆。

## 演示场景

- **A** 前方与后方攻击同时到达：前方招架、后方受击。
- **B** 长持续接触：接触约 1 秒后才进入防御，采用防御开始时刻作为判定时刻；
  偏角攻击展示精准扇形与格挡覆盖区的差异。
- **C** 窗口边缘：2249ms 招架、2250ms 格挡（半开区间），含突刺与重击。
- **D** 接触中切换塔盾即时获得格挡；退出姿态/换装不改写已结算裁决。
- **M** 手动操控：空格防御、A/D 转向、1-4 换装、G 假动作。

画面十字标记与 HUD 表格均显示**被采用的判定时刻**。渲染频率下拉框只改变重绘节奏，
逻辑始终按 10ms 固定步长推进（见 `test/scenarios.test.js` 的不变性测试）。
